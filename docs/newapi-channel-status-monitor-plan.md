# New API 分组模型状态监控实施计划

## 目标

在 New API `v1.0.0-rc.44` 增加登录用户可见的状态页，放在左侧“API 密钥”下方。监控维度固定为“分组 + 模型”，调用 New API 正常的分组路由；不按渠道逐条探测，也不宣称一个成功样本代表组内全部渠道健康。页面不显示缓存率。

## 安全边界

- 不使用管理员 API Key。管理员只负责创建、停用和调整专用普通用户及其 Key。
- 每个目标使用独立的普通用户 Key，Key 固定到目标分组，限制到目标模型，设置有限额度、有效期和 `127.0.0.1` 来源限制。
- 配置只保存 `probe_token_id`，不保存或返回 Key 明文。Key 不进入浏览器、响应 JSON、普通日志或计划文件。
- 空的 `CHANNEL_STATUS_MONITOR_TARGETS` 表示关闭主动探测；生产启用前先部署页面/API，再单独审核 Key、预算和目标配置。

## 行为契约

- 目标维度为 `group + model`，不配置渠道 ID；探测走正常分组路由和渠道选择。
- 真实用户请求优先作为观测数据。真实请求开始后，同目标的主动探测会被抑制；正在执行的探测会通过共享 Redis 的 owner 标记进行 best-effort 取消。
- 主动探测使用固定流式请求，记录首个非空内容时间、总耗时和输出速度。单次探测最多请求 8 个输出 Token。
- 页面显示状态、来源、首 Token、总耗时、输出速度和最近观测时间，不显示缓存率、渠道 ID、Key、提示词或上游原始错误。
- 后端从当前登录用户计算可用分组，用户不能通过请求参数越权查看其它分组。

## 配置格式

```json
[
  {
    "group": "standard",
    "model": "your-model",
    "probe_token_id": 123,
    "interval_seconds": 300,
    "timeout_seconds": 30
  }
]
```

配置通过环境变量 `CHANNEL_STATUS_MONITOR_TARGETS` 提供。每个 `group + model` 和 `probe_token_id` 必须唯一；间隔限制为 60-3600 秒，超时限制为 5-120 秒。配置错误、Redis 不可用或探测 Key 校验失败时 fail closed，不发送探测请求。

## 实施和验收

1. 在本地官方 `v1.0.0-rc.44` checkout 中完成后端、前端、Redis 状态存储、系统任务和测试。
2. 先以空配置部署页面/API，不创建生产探测 Key，不触发真实探测，不修改 B/D 容器、C 数据库、Redis 或 Nginx。
3. 审核目标分组、模型、Key ID、周期、超时、输出上限和预算后，再单独启用目标配置。
4. 验收登录权限过滤、Redis 标记生命周期、样本去重与过期、探测取消、SSE 终止事件、PAT 路由规则、前端无缓存率和刷新失败降级。

当前实现源码来自官方 tag `v1.0.0-rc.44`，生产环境尚未创建探测用户/Key，也尚未启用主动探测。
